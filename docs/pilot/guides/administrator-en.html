Administrator guide

System administrators: accounts, settings, security, backups. Administrator status does not allow treating patients.

Sign in. Sign in. Two-step verification is required. Keep the ten recovery codes safe and separate.
Trial username: adminPassword (given by the trial lead):

Your day

  1. Settings → Staff: add each person with a Role template, department and (separately) authorized services. Give a temporary password; they must change it.
  2. Settings → Services / Rooms / Appointment categories / Procedure codes: check against the clinic. Add the approved procedure codes (none are shipped).
  3. Settings → Security & Access → Accounts: reset a password, end sessions, reset two-step, rename a username.
  4. Recovery & Emergency: answer sign-in help requests (verify the person yourself first). Review every emergency-access use with a note.
  5. Alerts: read and acknowledge. Audit History: filter the log; Verify now checks it was not altered.
  6. Duplicates: approve links proposed by managers; Undo with a reason if wrong.
  7. Production readiness: every line should be OK before real data. Security Settings: passwords, idle minutes, limits.
  8. Backups: npm run backup:run and backup:drill on the server; restore only into a new file.
Do
  • Create accounts through role templates.
  • Verify identity before any reset.
  • Review emergency-access uses within 24 hours.
  • Deactivate leavers — never delete.
Don’t
  • Don’t share the administrator account.
  • Don’t switch off two-step verification.
  • Don’t use the trial system for real patient data.
If something goes wrong
  • No administrator can sign in: on the server, npm run mfa:reset -- <username>.
  • Readiness shows a failing line: open Docs → Go-live runbook, section 4.
Training material — synthetic data only. Never enter real patient data in the trial system.Trial questions? Ask the trial lead.
